# CC — базовая структура интерфейса

Эта папка содержит **blank UI** — нейтральный каркас интерфейса без привязки к окончательной бизнес-логике.

Референс задаёт композицию из трёх основных вертикальных зон:

```text
┌──────────────┬──────────────────────────────────────┬──────────────────┐
│              │              TOP MENU                │                  │
│              ├──────────────────────────────────────┤                  │
│ LEFT PANEL   │                                      │   RIGHT PANEL    │
│              │          CENTRAL CONTENT             │                  │
│              │                                      │                  │
└──────────────┴──────────────────────────────────────┴──────────────────┘
```

## 1. Left panel

Постоянная левая навигационная панель.

Назначение:

- основные разделы приложения;
- быстрые фильтры;
- список источников или коллекций;
- нижние системные пункты вроде Settings / Help.

В текущем blank-варианте используются условные пункты:

- Sources;
- All comments;
- Saved;
- Read;
- Deleted.

Верх панели содержит компактный логотип `CC`.

Активный пункт выделяется цветом и вертикальной полосой слева, как в референсе.

## 2. Central area

Центральная часть разделена на две зоны.

### 2.1. Top menu

Горизонтальная верхняя панель.

Это отдельная постоянная область над основным контентом.

В ней могут находиться:

- tabs текущего раздела;
- переключатели режима;
- фильтры;
- сортировка;
- поиск;
- действия над текущим экраном.

В blank-варианте показаны tabs:

- Comments;
- Unread;
- Saved;
- Deleted.

Важно: top menu не является частью прокручиваемого контента. Это самостоятельная зона layout.

### 2.2. Central content

Главная рабочая область приложения.

Здесь позже будут выводиться:

- список комментариев;
- источник;
- результаты поиска;
- коллекции;
- другие основные экраны.

В blank-варианте оставлены условные карточки-заглушки, чтобы видеть ритм и ширину контента.

Контент должен занимать максимум доступной ширины между боковыми панелями.

## 3. Right panel

Правая контекстная панель.

Она относится не ко всему приложению, а к текущему выбранному объекту.

Примеры того, что здесь может отображаться:

- информация о выбранном комментарии;
- данные автора;
- источник;
- статус;
- заметка пользователя;
- дополнительные действия;
- история или метаданные.

Верх правой панели имеет собственный header.

Ниже располагается контекстное содержимое с локальными tabs.

В blank-варианте используются:

- Info;
- Notes.

## 4. Иерархия интерфейса

Базовая модель:

```text
AppShell
├── LeftPanel
│   ├── Brand
│   ├── MainNavigation
│   └── BottomNavigation
│
├── Workspace
│   ├── TopMenu
│   └── CentralContent
│
└── RightPanel
    ├── ContextHeader
    └── ContextContent
```

Эту структуру желательно сохранить и при дальнейшем переходе на React-компоненты.

## 5. Принцип поведения панелей

### Desktop

Все три области видны одновременно:

```text
Left | Center | Right
```

Ориентировочная ширина:

- Left: `220px`;
- Center: занимает всё оставшееся пространство;
- Right: `320px`.

### Средняя ширина

Правая панель скрывается первой:

```text
Left | Center
```

Позже её можно открывать как drawer.

### Mobile

Основным становится центральный экран.

Левая и правая панели должны открываться как overlay/drawer, а не постоянно занимать ширину экрана.

## 6. Визуальные принципы

Референс используется прежде всего для структуры и визуального ритма, а не для буквального копирования содержимого.

Основные признаки:

- светлый фон;
- отдельная светло-жёлтая левая панель;
- чёткие тонкие разделители;
- чёрный текст;
- один акцентный цвет;
- минимум скруглений;
- компактные элементы навигации;
- много свободного пространства;
- визуально независимая правая колонка;
- активный верхний tab может отображаться чёрной плашкой.

## 7. Что пока не входит в blank UI

На этом этапе не реализуются:

- загрузка комментариев;
- работа с API;
- состояния Read / Saved / Deleted;
- реальная навигация;
- формы;
- модальные окна;
- база данных;
- бизнес-логика.

`index.html` нужен как визуальный каркас, на основе которого можно дальше строить приложение.
